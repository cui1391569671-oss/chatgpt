# 开发规则

本文件记录工作台项目的开发要求，后续新增或修改页面时均须遵守。

## 1. 页面内容不能超出整个页面

- 所有页面及组件必须适应当前可视区域，桌面端和移动端均不得出现横向溢出、内容越界或控件被裁切。
- 长文本、图片、GIF、表单、卡片及弹窗须在所属容器内合理换行、缩放或布局，不能撑破页面。
- 内容高度超过可视区域时，必须可以正常纵向滚动，确保所有内容和操作按钮可见、可达。
- 表格等确需横向滚动的内容，应限制在其自身容器内，不得导致整个页面横向滚动。
- 不得仅通过隐藏溢出来掩盖布局问题，也不得以裁切内容或按钮作为解决方式。
- 修改后须检查桌面及窄屏布局，测量主要容器的实际边界，并验证按钮可点击；不能只以页面没有横向滚动条作为验收依据。

## 2. 弹窗与抽屉统一开发要求

- 弹窗和抽屉的定位、宽高、最大高度及滚动区域由共享 Dialog / Sheet 组件统一管理。原生表单适配进共享组件后，旧容器不得继续保留固定定位、视口高度或独立宽度等冲突规则；应在原规则处排除已适配节点。
- 同一个弹窗只显示一套标题、说明和关闭按钮。适配旧页面时须隐藏旧标题栏及重复关闭按钮，保留业务代码依赖的原节点、ID、事件监听和保存逻辑；外部打开链接等独立操作应保留。
- 宽预览、个人中心、项目抽屉等尺寸差异须通过共享组件的明确变体或尺寸变量表达，不得靠旧页面选择器或追加高优先级样式覆盖。
- 抽屉采用固定头部与可滚动正文时，正文须允许收缩（如 flex 布局中的 min-height: 0），不得用正文最小高度撑出整个弹层。底部保存、取消及删除操作必须能够滚动到并点击。
- 长标题须合理换行或限制展示行数，不能挤压关闭按钮、覆盖说明或使正文失去可用高度；完整内容仍须可在相应字段中查看。
- 自动聚焦只能落到可见、可交互的控件，不能聚焦已隐藏的旧关闭按钮。关闭后应恢复合理焦点，取消和保存失败时须保留既有恢复行为。
- 修改共享弹窗逻辑后，须联查个人中心、消息通知、游戏发售列表、Google 表格预览、项目编辑与新增、笔记及衣物编辑，并检查 React 待办、年度计划和日历日程面板是否受到影响。
- 验收须等待入场动画结束，分别检查桌面和窄屏的实际弹层边界、重复标题与关闭按钮、内部滚动、底部操作可达性，以及保存、取消、失败恢复和焦点返回。不得只验证单个页面或只检查 document.scrollWidth。

## 3. 页面切换与共享节点保护

- 页面切换或替换内容区前，必须先把共享控件移回稳定的宿主容器，再卸载旧页面或挂载新页面。包括提前返回的 React 页面分支，不能只在普通页面分支处理。
- 共享“新建”按钮 `#add` 临时放入页面工具栏后，必须在下一次渲染入口统一移回 `.header-actions`，避免随 `#content.innerHTML` 替换被删除。
- 移动共享控件须保留原节点、ID 和事件绑定，不能通过复制按钮或重复绑定事件补救；任何时刻只能有一个对应共享节点。
- 页面专属组件与监听器须按既有生命周期卸载；异步回调更新界面前须确认目标页面和容器仍有效，不能覆盖已经切换到的页面。
- 不得仅增加空值判断来掩盖共享节点丢失；应修复节点归属和切换顺序，保证目标页面正常渲染、操作入口仍可用。
- 修改渲染入口、工具栏位置或组件卸载流程后，必须验证“普通页面 → React 页面 → 普通页面”以及返回原页面的连续切换，检查内容非空、共享节点唯一、按钮可操作且没有运行时错误。
- 娱乐记录相关回归至少覆盖与笔记、待办、年度计划、英语学习、居家健身、衣橱、设备维保及生活计划的往返切换；存在未保存编辑时仍须遵循原退出保护。

问题记录（2026-10-21）：娱乐记录将 `#add` 移入内容区后，切到健身页面时按钮随内容区清空，再切到笔记等页面触发 `Cannot set properties of null (setting 'textContent')`，导致页面空白。修复为在主渲染入口、所有提前返回分支之前统一回收共享按钮。验证细节见 [页面切换回归记录](verification/media-navigation.md)。

## 4. 表单布局与信息密度

- 按字段内容分配宽度：名称、备注、长链接可占整行；状态、平台、评分、日期和短数字字段使用紧凑宽度，不得默认全部拉满整行。
- 相关字段分组并排，例如状态与平台、开始与完成日期、当前进度与总进度。标签、帮助及错误提示须随对应字段一起布局，不能因并排而错位。
- 依据表单或弹窗的实际可用宽度换行，而非只判断整个浏览器宽度。空间不足时自动减少列数，所有字段容器须允许收缩，长选项不得撑破布局。
- 控件高度、字体、焦点和点击区域由共享组件统一管理，页面只负责字段宽度与排列。压缩留白不能以缩小触摸目标、裁掉选项或隐藏信息为代价。
- 页面工具栏、卡片和表单沿用共享间距；同一组控件保持对齐，避免短字段独占宽大行或无意义的空白。列表、长文本与封面按自身内容合理展示。
- 新增或替换控件时，必须同时验收控件、字段宽度、分组与窄屏表现，不能只确认控件能输入或选择。
- 验收至少覆盖桌面、中等宽度和手机；检查长选项、旧值、空值、必填和错误提示，验证保存、取消、失败恢复及底部操作可达。日期顺序及业务校验须保持不变。
- 检查所有页面时须记录页面与主要表单的覆盖范围、发现的问题、修复及未验证项，不能以单个页面通过代替全站验收。
