# 工作台开发规范

本文件是工作台开发规范的唯一正文，统一维护开发与验收规则、代码与样式归属、视觉设计及功能行为约定。开发前须阅读，完成后和上线前须再次逐项复核；不得只以测试通过代替规范验收。

原有独立的设计与行为规范已迁入本文件，不再维护多份正文。`AGENTS.md` 仅作为开发工具自动发现的入口，不承载另一套规则。后续技能或流程需要设计上下文、UX contract 时，读取本文件对应章节，不另建重复规范。

部署、数据接口及专项使用说明保留为参考资料；`verification/` 是历史验证证据，不替代现行规则。两边修改规范时合并到本文件：重复规则去重，互补规则保留，明确被新决定取代的旧口径在原处更新；未确认的业务冲突须核对实现与用户决定，不能自动用本地或远端版本覆盖。

## 开发与交付检查

- 开发前阅读本文件，确认本次修改适用的规则；开发完成后须再次以本文件为依据，逐项检查最终实现，不能只参考测试结果或本次需求描述。
- 完成汇报和上线前，须核对适用规则是否满足，并完成相应的构建、测试、浏览器操作及布局验证。发现不符合项时先修复，再重新检查受影响的部分。
- 不适用的规则应按本次范围判断；未验证、受阻或仍有问题的项目须如实说明，不得标记为通过，也不得以“测试通过”代替开发规范验收。

## 代码与样式归属

用户要求：后续不要采用追加覆盖样式的方式开发网站。

新增或替换功能必须先确认旧控件、DOM、事件、样式及调用方归属；完成业务绑定迁移后删除已废弃的控件渲染、监听和冲突规则，不得把一套新控件盖在旧控件上，或仅隐藏完整旧实现长期并存。一个交互区域只能有一个可见、可聚焦的控件所有者。仍被业务表单或第三方组件管理的原节点，仅可作为明确的兼容桥保留，须隔离其可见性/焦点并写明依赖；不得直接删除仍在使用的字段、记录或监听。共享组件不能再被旧适配器套用第二套控件样式。验收须检查初次打开、交互后、重复打开、连续切页及不同宽度下的重叠、重复入口和焦点，不以单纯无页面溢出代替。

- Shared tokens: pinned `theme-presets/shadcn-glass-ui` → generated `glass-preset.css`; aliases in `admin-theme.css`.
- Shared layout, materials and canonical control metrics: `workspace.css`. Modify the owning rule directly. Do not append a new override stylesheet, increase selector specificity, or add `!important` to win a conflict.
- Page-specific business layout: `workbench-page.css` and `projects-page.css`. Do not redefine shared control height, radius, typography or theme colors there.
- React behavior/component markup: `tasks-ui/src/components/` and `workspace-primitives.tsx`; behavioral variants belong in shared primitives. Preserve native form IDs, listeners and persistence semantics.
- `tasks-ui/src/style.css` owns React layout and utility integration; shared visual specifications must reference workspace tokens, not independently copy values.
- Native adapted forms retain their original nodes. Their visible title/description/close controls come from the shared Dialog header. Do not remove nodes referenced by business code.
- Existing higher-specificity/important rules are migration debt, not a template for new code. Remove conflicting declarations at their source before changing an owner.
- Do not hand-edit generated HTML style blocks, `pages.mjs`, `tasks-assets.mjs` or `glass-theme.mjs`. Rebuild changed component assets and pages.
- Verify native and React forms together, save/failure recovery, focus return, nested scrolling, and narrow viewports before delivery.

- Search, authored business dates and feedback must use WorkspaceSearch/enhanceWorkspaceSearch, WorkspaceDateInput/DateChooser and WorkspaceFeedback. Do not introduce OS date popups or browser alert/confirm. Calendar retains its official authored form/recurrence components.
- Responsive checks must measure actual main/toolbar/dialog bounds and clickable hit targets, not only document scrollWidth; a clipped zero-width main is a failure even when the document does not overflow.

## 通用开发规则

### 所有页面动效统一（2026-10-26）

- 工作空间、私人空间、项目问题独立页及嵌入页、账号与登录页、公开官网均遵循同一动效体系。同类卡片、导航、按钮、勾选、进度、反馈、弹窗与抽屉必须复用已有共享组件和策略；不得为单独页面另设一套动画、时序或重复叠加同类效果。官网按内容展示用途使用该体系，不套用业务表单动效。
- 动效参数由 workspace-theme.css 统一定义，React 与原生适配通过 workspace-motion-policy.ts 读取或执行；页面样式只引用共享令牌，不另写同类动效常量。卡片入场500ms、上移18px、逐张间隔70ms且总延迟最多280ms；标题480ms；功能反馈及弹层入场240ms、退场180ms。同类交互保持一致，不要求所有功能使用同一种动画。
- 卡片使用 AnimatedContent，按所属内容滚动容器触发；嵌套卡片只由最外层执行入场，不能同时做整页和逐卡入场。每次进入页面可播放一次，同页保存、筛选、轮询、刷新记录及DOM重建不得重复播放已完成的卡片。按稳定卡片或记录标识去重；列表重排只表达位置变化，不额外叠加入场。
- 日历、甘特图及其他坐标敏感区域不添加装饰性位移，保留原拖动、滚动和浮层定位。导航弹性、通知铃铛、完成勾选、渐变标题及进度等专项动效由各自共享组件统一拥有；健身教学GIF属于用户可控内容，遵守既有播放/暂停规则，不当作页面装饰。
- 系统减少动态效果为最高优先级，切换后立即停止正在运行的装饰动画，保留内容、选中状态、业务反馈和可用操作。离屏、后台、切页及卸载按对应组件生命周期暂停或清理RAF、计时器、观察器、事件及动画实例；恢复时不重放已完成的入场。
- 动效不能推迟保存、导航或其他业务操作，不改变记录与保存/失败恢复管线，不替换业务节点，不阻挡鼠标或键盘，不引起横向溢出、布局跳动、焦点丢失或重复控件。新增页面必须自动继承共享体系；存在必要差异须记录具体用途及共享变体，不能靠页面级覆盖。
- 验收覆盖所有受影响页面在桌面与窄屏的首次进入、连续切页、同页刷新、长列表/空状态、键盘与减少动态效果；共享弹层还须检查打开/关闭及焦点返回。检查实际边界、可点击性及动画清理，不能只以构建通过或无横向滚动条作为全部通过的依据；未覆盖项如实记录。

### 页面内容不能超出整个页面

- 所有页面及组件必须适应当前可视区域，桌面端和移动端均不得出现横向溢出、内容越界或控件被裁切。
- 长文本、图片、GIF、表单、卡片及弹窗须在所属容器内合理换行、缩放或布局，不能撑破页面。
- 内容高度超过可视区域时，必须可以正常纵向滚动，确保所有内容和操作按钮可见、可达。
- 表格等确需横向滚动的内容，应限制在其自身容器内，不得导致整个页面横向滚动。
- 表格采用固定头部与内部滚动时，面板、结果包装层和滚动容器须形成完整可收缩的布局链；不能让中间层被内容撑高后由外层裁切。必须实际滚动到最后一条记录验证可达性，刷新后保留纵向和横向查看位置。
- 不得仅通过隐藏溢出来掩盖布局问题，也不得以裁切内容或按钮作为解决方式。
- 修改后须检查桌面及窄屏布局，测量主要容器的实际边界，并验证按钮可点击；不能只以页面没有横向滚动条作为验收依据。

### 弹窗与抽屉统一开发要求

- 弹窗和抽屉的定位、宽高、最大高度及滚动区域由共享 Dialog / Sheet 组件统一管理。原生表单适配进共享组件后，旧容器不得继续保留固定定位、视口高度或独立宽度等冲突规则；应在原规则处排除已适配节点。
- 同一个弹窗只显示一套标题、说明和关闭按钮。适配旧页面时须隐藏旧标题栏及重复关闭按钮，保留业务代码依赖的原节点、ID、事件监听和保存逻辑；外部打开链接等独立操作应保留。
- 宽预览、个人中心、项目抽屉等尺寸差异须通过共享组件的明确变体或尺寸变量表达，不得靠旧页面选择器或追加高优先级样式覆盖。
- 抽屉采用固定头部与可滚动正文时，正文须允许收缩（如 flex 布局中的 min-height: 0），不得用正文最小高度撑出整个弹层。底部保存、取消及删除操作必须能够滚动到并点击。
- 长标题须合理换行或限制展示行数，不能挤压关闭按钮、覆盖说明或使正文失去可用高度；完整内容仍须可在相应字段中查看。
- 自动聚焦只能落到可见、可交互的控件，不能聚焦已隐藏的旧关闭按钮。关闭后应恢复合理焦点，取消和保存失败时须保留既有恢复行为。
- 受控确认框及抽屉可通过共享 `DialogContent` / `SheetContent` 的 `returnFocus` / `returnFocusFallback` 解析关闭后的当前节点；两者复用同一焦点恢复规则。列表节点可能在保存或失败后重建，业务入口应按稳定记录 ID 取得当前按钮。取消回到原入口，成功删除入口已消失时移交稳定的后续操作；既有 `onCloseAutoFocus` 显式回调及其 `preventDefault()` 优先。
- 修改共享弹窗逻辑后，须联查个人中心、消息通知、游戏发售列表、Google 表格预览、项目编辑与新增、笔记及衣物编辑，并检查 React 待办、年度计划和日历日程面板是否受到影响。
- 验收须等待入场动画结束，分别检查桌面和窄屏的实际弹层边界、重复标题与关闭按钮、内部滚动、底部操作可达性，以及保存、取消、失败恢复和焦点返回。不得只验证单个页面或只检查 document.scrollWidth。

### 功能职责、数据来源与重复入口

- 新增或修改功能前，须检查现有页面、操作入口和数据集合是否已提供同类能力。已有能力优先复用或扩展，不再建立功能相同、需要用户重复维护的独立记录。
- 同一业务对象应有明确的主要维护页面和数据来源。日历、今日任务、到期提醒等汇总页面从原记录派生，通过稳定 ID 关联，不额外复制业务记录；各视图应明确自己的日期范围、状态筛选和用途。
- 相似功能须明确职责：习惯打卡记录不固定时间的每日习惯；重复日程管理具体时间安排；年度计划管理长期目标和进度；项目问题管理项目跟进；普通待办管理其他执行事项。需要联动时建立明确关联，不自动复制或仅凭标题相同合并。
- 游戏名称、平台、游玩状态和进度由娱乐记录统一管理。私人待办通过 mediaRecordId 关联游戏，仅承担执行安排与到期提醒；完成待办不得自动改变游戏状态或推断通关日期。关联作品被删除时，提醒仍保留，明确提示关联失效并允许解除关联。
- 工作与私人空间的相似功能保留数据隔离，不能因界面相似而合并数据；账号级共享资料遵守其独立权限与存储规则。
- 同一操作可以保留必要的快捷入口，但须复用同一表单、校验、保存及失败恢复流程。新建项目的菜单、问题下拉和项目管理入口统一使用 projectCreate；嵌套创建须保留父表单草稿，成功后选中新项目，取消或保存后恢复合理焦点。
- 同一区域中指向相同结果的按钮应精简。待办标题承担编辑入口；单词练习保留顶部词库入口和进行中的结束练习确认。不得重新增加已移除的重复编辑、返回或首页入口，除非有明确且记录在案的新用途。
- 旧实现、重复事件绑定及不可达分支须在确认无调用、无数据兼容依赖后清理。构建生成的页面与资源不属于应手工删除的重复代码；既有数据兼容不能随旧入口一并移除。

### 旧数据整理与跨页面回归

- 旧数据合并、迁移或关联须先提供预览，明确将新增、关联及保留哪些记录，由用户确认后执行。默认不自动处理，不根据同名记录猜测关联，不推断缺失的业务状态或日期。
- 整理时须保留原记录的稳定 ID、日期、详情和完成状态等已有信息。多集合变更沿用记录级 patch、原子保存及冲突检查；重试复用新记录 ID，防止部分保存或重复新增。取消不写入，失败保留选择与输入。
- 多条旧记录应分组展示并保留跨组选择，长标题与窄屏下的确认、取消操作均须可达。不得在页面加载或版本上线时自动执行数据整理。
- 修改共享组件、数据来源或弹层识别逻辑后，须检查相关页面的正常操作、取消、保存失败重试、冲突处理、焦点返回及桌面/窄屏表现。弹层识别须限制在所属功能及宿主范围，不能把其他页面的下拉框、日期框或对话框误归入当前组件。
- 验证使用隔离测试数据；不得将本地演示记录、生产业务数据、密钥或缓存混入发布文件。发布前核对生产分支差异，仅包含本次已确认的修改，并如实区分构建、自动测试、本地浏览器验证与生产部署结果。

### 卡片与列表的信息密度

- 工作台的卡片与列表应优先保证信息集中、便于扫描，避免短内容占用过高卡片、多层重复间距或不必要的空白。留白须服务于分组、阅读或操作，不以固定大高度撑开记录。
- 标题、状态、优先级、日期等短信息在空间允许时集中排列，说明紧接其下；多条记录优先采用紧凑列表行，避免每项都拆成多层卡片。窄屏自然换行，必要时将操作按钮另起一行。
- 紧凑布局不得靠缩小正文或状态文字、裁切长内容、隐藏必要信息或挤压操作区实现。勾选框和按钮等交互目标保持项目既定的至少44px可点击区域；可见图标大小与实际点击区域应区分。
- 长标题、连续长字符串、多行说明、空记录及多条记录均须保持可读、可滚动和可操作；如业务确需折叠说明，须提供明确的展开入口，不能仅用省略或隐藏代替完整内容。
- 密度差异通过共享组件的明确变体或布局变量表达。卡片内边距由 workspace.css 的共享规则管理，紧凑卡片复用 workspace-card-compact / --card-padding；页面样式只负责业务排列，不新增高优先级覆盖来改变共享控件规格。
- 修改后按相同内容、相同视口对比实际高度和信息排列，并检查桌面、平板及320px/390px窄屏的换行、点击区域和按钮边界；同时确认未使用紧凑变体的其他页面间距不受影响。完成、编辑、删除、筛选及失败恢复等现有行为仍须正常。

### 页面切换与共享节点保护

- 页面切换或替换内容区前，必须先把共享控件移回稳定的宿主容器，再卸载旧页面或挂载新页面。包括提前返回的 React 页面分支，不能只在普通页面分支处理。
- 共享“新建”按钮 `#add` 临时放入页面工具栏后，必须在下一次渲染入口统一移回 `.header-actions`，避免随 `#content.innerHTML` 替换被删除。
- 移动共享控件须保留原节点、ID 和事件绑定，不能通过复制按钮或重复绑定事件补救；任何时刻只能有一个对应共享节点。
- 页面专属组件与监听器须按既有生命周期卸载；异步回调更新界面前须确认目标页面和容器仍有效，不能覆盖已经切换到的页面。
- 不得仅增加空值判断来掩盖共享节点丢失；应修复节点归属和切换顺序，保证目标页面正常渲染、操作入口仍可用。
- 修改渲染入口、工具栏位置或组件卸载流程后，必须验证“普通页面 → React 页面 → 普通页面”以及返回原页面的连续切换，检查内容非空、共享节点唯一、按钮可操作且没有运行时错误。
- 娱乐记录相关回归至少覆盖与笔记、待办、年度计划、英语学习、居家健身、衣橱、设备维保及生活计划的往返切换；存在未保存编辑时仍须遵循原退出保护。

问题记录（2026-10-21）：娱乐记录将 `#add` 移入内容区后，切到健身页面时按钮随内容区清空，再切到笔记等页面触发 `Cannot set properties of null (setting 'textContent')`，导致页面空白。修复为在主渲染入口、所有提前返回分支之前统一回收共享按钮。验证细节见 [页面切换回归记录](verification/media-navigation.md)。

### 表单布局与信息密度

- 按字段内容分配宽度：名称、备注、长链接可占整行；状态、平台、评分、日期和短数字字段使用紧凑宽度，不得默认全部拉满整行。
- 相关字段分组并排，例如状态与平台、开始与完成日期、当前进度与总进度。标签、帮助及错误提示须随对应字段一起布局，不能因并排而错位。
- 依据表单或弹窗的实际可用宽度换行，而非只判断整个浏览器宽度。空间不足时自动减少列数，所有字段容器须允许收缩，长选项不得撑破布局。
- 控件高度、字体、焦点和点击区域由共享组件统一管理，页面只负责字段宽度与排列。压缩留白不能以缩小触摸目标、裁掉选项或隐藏信息为代价。
- 页面工具栏、卡片和表单沿用共享间距；同一组控件保持对齐，避免短字段独占宽大行或无意义的空白。列表、长文本与封面按自身内容合理展示。
- 新增或替换控件时，必须同时验收控件、字段宽度、分组与窄屏表现，不能只确认控件能输入或选择。
- 验收至少覆盖桌面、中等宽度和手机；检查长选项、旧值、空值、必填和错误提示，验证保存、取消、失败恢复及底部操作可达。日期顺序及业务校验须保持不变。
- 检查所有页面时须记录页面与主要表单的覆盖范围、发现的问题、修复及未验证项，不能以单个页面通过代替全站验收。

### 行为 Word practice

跟打显示英文，默写隐藏英文及音标直至查看答案或提交结果；输入在IME组合期间不提交。错误拼写不自动前进且允许修改；本轮拼错、查看答案或暂时不会的词记为不会，首次正确记为已掌握；每次成功提交增加一次复习次数并记录日期，首次学习日期已有时保留。每词使用原 vocabulary 记录级patch 保存，失败保留当前输入并允许重试，不前进或重复计数；成功后才能进入下一词。统计仅针对本轮，错词可单独重练；不宣称间隔重复算法。练习期间阻止外部导航和后台刷新；退出确认只影响未提交答案，已提交记录保留。朗读使用浏览器英语语音，失败明确提示并在退出时停止。

单词练习直接渲染在英语学习页面，不以模态弹窗展示。词汇库独立路由 `vocabularyLibrary` 保留导入、搜索、熟练度筛选和词条；练习页右上入口和词库返回按钮双向导航。练习进行中切换词库须确认；设置与完成状态允许正常导航，跨页面卸载 React 根并停止朗读，重新进入后正确重建。词汇库路由保持英语学习侧栏的选中状态。

### 行为 English practice completion records
A completed round is saved atomically with the final word review in the private `wordPracticeSessions` collection. Each record contains a stable round ID, mode, start/completion timestamps, completion date in Asia/Shanghai, word count, first-attempt correct count, and elapsed seconds. Retry reuses the round ID; partial rounds are not recorded as completed. Failed saves preserve the final answer and allow retry. Shared collection patches preserve concurrent sessions and unrelated vocabulary/review data. Work-space writes to this collection are rejected. Existing data needs no migration.

### 行为 Home fitness
