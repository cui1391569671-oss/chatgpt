本文件是工作台开发规范的唯一正文，统一维护开发与验收规则、代码与样式归属、视觉设计及功能行为约定；开发前阅读，完成后与上线前逐项复核。`AGENTS.md` 只是开发工具自动发现的入口，不承载另一套规则。部署、数据接口与专项说明属参考资料，`verification/` 是历史证据，均不替代本文件。规范变更合并到本文件：重复去重、互补保留、被取代的旧口径在原处更新；未确认的业务冲突须核对实现与用户决定，不能自动用本地或远端版本覆盖。

## 开发与交付检查

开发前确认本次适用的条目；完成后与上线前按同一文件重新核对，发现不符合项先修复，再复检受影响部分。不适用的按本次范围判断；未验证、受阻或仍有问题的须如实说明，不得标记为通过，也不得以“测试通过”代替规范验收。

- 通用验收：覆盖桌面与窄屏（1280 / 390 / 320px），测量主区、工具栏、弹层与点击目标的实际边界，不以 document.scrollWidth 或无横向滚动条作为通过依据。原生与 React 表单须一并验证，包括保存成功、失败重试、取消、焦点返回、嵌套滚动与未保存退出保护。
- 构建与检查：执行 `npm run verify`（资源一致性、lint/typecheck 基线、Node 测试），并完成受影响页面的浏览器操作；生成的 `pages.mjs` 与组件资源须重建后提交。
- 汇报与隔离：区分构建、自动测试、本地浏览器验证与生产部署结果，未覆盖项写明；验证使用隔离数据，不把演示记录、生产数据、密钥或缓存混入发布文件。

## 代码与样式归属

用户要求：后续不要采用追加覆盖样式的方式开发网站。

新增或替换功能先确认旧控件、DOM、事件、样式与调用方的归属；完成绑定迁移后删除废弃渲染、监听与冲突规则，不得把新控件盖在旧实现上长期并存。一个交互区域只能有一个可见、可聚焦的控件所有者。仍被业务或第三方组件管理的原节点仅作显式兼容桥保留，须隔离可见性/焦点并写明依赖。共享组件不得被旧适配器套用第二套控件样式。

- 令牌：固定 `theme-presets/shadcn-glass-ui` → 生成 `glass-preset.css`；语义别名在 `admin-theme.css`。
- 共享布局、材质与控件规格：`workspace.css`。直接修改所属规则，不新增覆盖表、不提高选择器权重、不用 `!important` 争胜。
- 页面业务布局：`workbench-page.css`、`projects-page.css`，不重定义共享控件的高度、圆角、字体或主题色。
- React 行为与组件：`tasks-ui/src/components/`、`workspace-primitives.tsx`，行为变体归共享原语；保留原生表单 ID、监听与持久化语义。
- `tasks-ui/src/style.css` 负责 React 布局与工具类；共享视觉引用工作区令牌，不复制数值。
- 原生适配表单保留原节点，可见标题、说明与关闭按钮来自共享 Dialog 头；不删除业务引用的节点、字段或监听。
- 已有高权重或 `!important` 规则是迁移债，不是新代码模板；改变归属前先在源头删除冲突声明。
- 生成物（`pages.mjs`、`tasks-assets.mjs`、`glass-theme.mjs` 等）只通过构建更新。

搜索、业务日期与反馈统一使用 WorkspaceSearch / enhanceWorkspaceSearch、WorkspaceDateInput / DateChooser 与 WorkspaceFeedback，不引入系统日期弹窗或浏览器 alert/confirm；日历保留其官方表单与重复规则组件。响应式检查测量实际边界与点击目标，主区宽度为零即失败。

## 页面与布局标准

页面之间的一致性由令牌、断点、骨架三件事保证。新增页面直接符合；存量页面按预算逐步收敛，不要求一次性重写。

### 令牌

| 类别 | 令牌 | 值 |
|---|---|---|
| 间距 | `--space-1` … `--space-12` | 4 / 8 / 12 / 16 / 24 / 32 / 48px |
| 字号 | `--type-caption` … `--type-display` | 12 / 14 / 16 / 18 / 28px |
| 控件高度 | `--control-height` | 44px |
| 层级 | `--z-sticky` / `--z-overlay` / `--z-modal` / `--z-toast` | 10 / 100 / 200 / 300 |
| 圆角 | 沿用 `--control-radius`、`--radius-xl` | 见「已知冲突」 |

页面样式只引用令牌，不写裸像素；`0` 与 `1px` 边框除外。新增令牌只加在 `workspace-theme.css` 的 `:root`，并重新生成 `glass-preset.css`。

### 断点

只用四档：320、480、768、1100；验收宽度 320 / 390 / 768 / 1280。存量文件中的 360、374、420、520、600、640、641、760、767、900、1000 已登记在 `scripts/style-budget.json`，不得再新增；改动这些区域时顺带归并到四档。

### 页面骨架

每个视图固定四个槽位，顺序不变：

1. `PageHeader`：标题、可选说明、主操作。私有视图用 `workspace-page-hero`，工作视图沿用现有标题区，同一视图不得混用两套。
2. `Toolbar`：搜索、筛选、视图切换；同行控件对齐，窄屏换行而非横向溢出。
3. `Content`：卡片、列表或表格，按下方矩阵选择。
4. `StateLayer`：空、加载、错误三态在同一容器内切换，不整页替换，不伪装成加载。

新增视图必须四槽齐全；缺少空态或错误态的页面不得上线。

### 页头

页头只有两种变体，统一挂在 `.workspace-page-header` 契约下，新页面按所属空间选一种，不得新增第三套，也不得在同一页面混用：

| 变体 | 用于 | 结构与现状 |
|---|---|---|
| `data-variant="hero"` | 私人空间的功能页 | 大标题 28px（手机 24px）+ 说明 + 主操作，竖排留白较多 |
| `data-variant="compact"` | 工作空间的常规页 | eyebrow（日期）+ 标题 + 操作行，密度高 |

- `hero` 已由 `.workspace-page-hero` 实现，并同时接受 `.workspace-page-header[data-variant="hero"]` 别名；新代码使用后者。
- `compact` 由 shell 的单例 `<header>` 承担，标题与 eyebrow 的读写统一走 `setPageHeader({title, eyebrow})`（同时暴露为 `window.WorkspacePageHeader.set`）。新代码与适配器不得直接写 `$('heading').textContent`，也不得自行创建第二个页头节点。
- 迁移顺序：先迁 React 功能面板（`fitness` 等已用 hero），再迁原生视图；每次只迁一个页面，验收四档断点与操作区对齐。
- 页头文案与页面标题一致，不重复出现第二处标题说明区。

### 状态层

三态统一用 `.workspace-state`，由 `data-state` 区分，视觉与间距归 `workspace.css`：

```html
<div class="workspace-state" data-state="empty" role="status">
  <strong>标题</strong>
  <p>一句说明</p>
  <button class="btn" type="button">可选操作</button>
</div>
```

- `data-state` 取 `empty`、`loading`、`error`；加载态加 `role="status"`。
- 标题用 `<strong>`，说明用 `<p>`，操作按钮直接放在容器内，不另包一层卡片。
- 不再用 `.empty`、`.card empty`、`.site-empty`、`.workspace-empty-state` 表达状态；`.workspace-empty-state` 只作旧引用兼容保留。
- 文案说明现状与下一步，不伪装成加载，也不伪造数据。

`workbench.html` 的部分区块由 `*-adapter.js`、`today-tasks-page.js` 等源文件内联生成：改标记要改源文件再跑 `npm run build:pages`，直接改 HTML 会被构建覆盖。

### 呈现方式矩阵

| 场景 | 用什么 |
|---|---|
| 少量关键信息、需要强调 | 卡片，密度用 `workspace-card-compact` 调整 |
| 同类多条、需要快速扫描 | 紧凑列表行 |
| 需要横向比较多列 | 表格，宽表在自身容器内滚动 |
| 2–3 个互斥视图 | WorkspaceSegment |

### 执行与验收

- `npm run check:style`（`scripts/style-audit.mjs`）检查裸像素与断点：新增 CSS 文件必须零裸像素且只用四档断点；存量文件不得超过 `scripts/style-budget.json` 的登记值。
- `npm run check:markup`（`scripts/markup-audit.mjs`）检查骨架规则：标题必须经 `setPageHeader`，不得直接写 `$('heading').textContent`；页面状态必须用 `.workspace-state`，不得回退到 `.empty`、`card empty`、`site-empty`、`workspace-empty-state`。
- 预算只减不增；某文件裸像素下降后，同步下调其登记值。
- 新页面验收：四档断点各看一次，四槽齐全，三态均有实际内容。

### 已知冲突（待决议，勿擅自改）

`--control-radius` 当前是 24px，用于导航项、周条与提示条；而 `workspace.css` 中按钮与输入大量使用字面 `10px`，与「普通控件圆角 10px」的表述不一致。确认视觉归属前，新增控件沿用 10px 字面值或既有令牌，不引入第三个圆角值。

## 通用开发规则

### 动效统一

- 工作空间、私人空间、项目问题页、账号登录页与公开官网共用同一动效体系；同类卡片、导航、按钮、勾选、进度、反馈、弹层必须复用共享组件与策略，不为单个页面另设时序，也不叠加同类效果。官网按内容展示用途使用，不套用业务表单动效。
- 参数由 `workspace-theme.css` 统一定义，React 与原生经 `workspace-motion-policy.ts` 读取；卡片入场 500ms、上移 18px、逐张间隔 70ms、总延迟 ≤280ms，标题 480ms，功能反馈与弹层入场 240ms、退场 180ms。
- 卡片使用 AnimatedContent，由所属滚动容器触发，嵌套卡片只由最外层入场；同页保存、筛选、轮询与 DOM 重建不重播已完成的入场，按稳定 ID 去重。
- 日历、甘特图等坐标敏感区域不加装饰性位移；铃铛、勾选、渐变标题与进度动效由各自共享组件拥有；健身 GIF 属用户可控内容，按既有播放/暂停规则处理。
- 页面装饰使用固定版本 React Bits：AnimatedContent 负责卡片入场，SpotlightCard 淡紫聚光，Magnet 按钮位移 ≤2px、封面倾斜 7 度，ClickSpark 点击与完成反馈，BlurText 完成提示；功能性导航、列表重排与弹层沿用既有无障碍宿主并复用同套时序。
- 减少动态效果为最高优先级：切换后立即停止装饰动画，保留内容、选中态与业务反馈；离屏、后台、切页与卸载按组件生命周期清理 RAF、计时器、观察器与事件。
- 动效不得推迟保存、导航或阻挡输入，不替换业务节点，不引起溢出、布局跳动、焦点丢失或重复控件；新增页面自动继承，必要差异须记录用途与共享变体。

### 页面边界与滚动

- 所有页面必须适应当前视口，桌面与移动端都不得横向溢出、内容越界或控件被裁切；长文本、图片、GIF、表单、卡片与弹窗在所属容器内换行、缩放或布局。
- 内容高于视口时须可正常纵向滚动，所有内容与操作可达；表格等确需横向滚动的内容限制在自身容器内，不得带动整页滚动。
- 表格固定头部并内部滚动时，面板、包装层与滚动容器须形成可收缩的布局链，不能由中间层撑高后被外层裁切；须实际滚到最后一条记录验证可达，刷新后保留纵横位置。
- 不得用隐藏溢出掩盖布局问题，也不得以裁切内容或按钮作为解决方案。

### 弹窗与抽屉

- 定位、宽高、最大高度与滚动区域由共享 Dialog / Sheet 统一管理；原生表单适配后，旧容器不得保留固定定位、视口高度或独立宽度等冲突规则。
- 同一弹窗只显示一套标题、说明与关闭按钮；适配旧页面时隐藏旧标题栏与重复关闭按钮，保留业务依赖的节点、ID、监听与保存逻辑，外部打开链接保留。
- 宽预览、个人中心、项目抽屉等尺寸差异通过共享变体或尺寸变量表达，不靠旧选择器或追加高权重样式。
- 抽屉采用固定头部与可滚动正文时，正文须允许收缩（如 `min-height: 0`）；底部保存、取消、删除必须能滚动到并点击。
- 长标题合理换行或限制行数，不挤压关闭按钮或说明；完整内容仍须可在字段中查看。
- 自动聚焦只落到可见可交互控件，不能聚焦已隐藏的旧关闭按钮；关闭后恢复合理焦点，取消与保存失败沿用既有恢复行为。
- 受控确认框与抽屉通过共享 `DialogContent` / `SheetContent` 的 `returnFocus` / `returnFocusFallback` 解析关闭后的节点，列表重建后按稳定记录 ID 取当前按钮；`onCloseAutoFocus` 显式回调及其 `preventDefault()` 优先。
- 修改共享弹窗逻辑后，须联查个人中心、消息通知、游戏发售列表、Google 表格预览、项目编辑与新增、笔记与衣物编辑，以及 React 待办、年度计划与日历日程面板。
- 验收等待入场动画结束后，检查桌面与窄屏的实际边界、重复标题与关闭按钮、内部滚动、底部操作可达，以及保存、取消、失败恢复与焦点返回。

### 功能职责与重复入口

- 新增或修改功能前，检查现有页面、入口与数据集合是否已提供同类能力；已有能力优先复用或扩展，不建立功能相同、需要用户重复维护的独立记录。
- 同一业务对象有明确的主要维护页面与数据来源；日历、今日任务、到期提醒等汇总视图从原记录派生、按稳定 ID 关联，各视图明确自身日期范围、状态筛选与用途。
- 职责划分：习惯打卡记录不固定时间的每日习惯；重复日程管理具体时间安排；年度计划管理长期目标与进度；项目问题管理项目跟进；普通待办管理其他执行事项。需要联动时建立明确关联，不自动复制或按同名合并。
- 游戏名称、平台、状态与进度由娱乐记录统一管理；私人待办通过 `mediaRecordId` 关联，只承担执行与提醒，完成待办不改变游戏状态或推断通关日期。关联作品被删除时提醒保留，明确提示关联失效并允许解除。
- 工作与私人空间的相似功能保持数据隔离，不因界面相似而合并数据。
- 同一操作可有快捷入口，但须复用同一表单、校验、保存与失败恢复；项目创建统一使用 `projectCreate`，嵌套创建保留父表单草稿、成功选中新项目、取消后恢复焦点。
- 同一区域指向相同结果的按钮应精简：待办标题承担唯一编辑入口，单词练习保留顶部词库入口与进行中的结束练习确认，操作区保留删除与关联作品入口；不得重新增加已移除的重复编辑、返回或首页入口，除非有记录在案的新用途。“每日清单”改称习惯打卡，年度目标与日历排期的职责通过说明区分。
- 旧实现、重复事件绑定与不可达分支，在确认无调用与数据兼容依赖后清理；构建生成的页面与资源不属于手工删除的重复代码。

### 旧数据整理与跨页面回归

- 旧数据合并、迁移或关联须先预览，说明将新增、关联与保留哪些记录，由用户确认后执行；默认不自动处理，不按同名猜测关联，不推断缺失状态或日期。
- 整理须保留原记录的稳定 ID、日期、详情与完成状态；沿用记录级 patch、原子保存与冲突检查，重试复用新 ID，防止部分保存或重复新增；取消不写入，失败保留选择与输入。
- 多条旧记录分组展示并保留跨组选择，长标题与窄屏下的确认、取消均须可达；不得在页面加载或上线时自动执行整理。
- 修改共享组件、数据来源或弹层识别逻辑后，检查相关页面的正常操作、取消、保存失败重试、冲突处理、焦点返回与桌面/窄屏表现；弹层识别限制在所属功能与宿主范围，不误收其他页面的下拉、日期框或对话框。

### 卡片与列表的信息密度

- 优先保证信息集中、便于扫描，避免短内容占高卡片、多层重复间距或无意义留白；留白服务于分组、阅读与操作，不用固定大高度撑开记录。
- 标题、状态、优先级、日期等短信息在空间允许时集中排列，说明紧接其下；多条记录优先紧凑列表行，窄屏自然换行，必要时操作按钮另起一行。
- 紧凑不得靠缩小正文或状态文字、裁切内容、隐藏信息、挤压操作区实现；勾选框与按钮保持至少 44px 点击区域，可见图标尺寸与实际点击区区分。
- 长标题、连续长字符串、多行说明、空记录与多条记录须保持可读、可滚动、可操作；需折叠时提供明确展开入口，不能以省略代替完整内容。
- 密度差异通过共享变体或布局变量表达；卡片内边距由 `workspace.css` 管理，紧凑卡片复用 `workspace-card-compact` / `--card-padding`，页面只负责业务排列。
- 修改后按相同内容与视口对比实际高度与排列，检查桌面、平板及 320/390px 的换行、点击区域与按钮边界，确认未使用紧凑变体的页面不受影响。

### 页面切换与共享节点保护

- 切换或替换内容区前，先把共享控件移回稳定宿主，再卸载旧页面或挂载新页面；提前返回的 React 分支同样处理。
- 共享“新建”按钮 `#add` 临时放入页面工具栏后，须在下一次渲染入口统一移回 `.header-actions`，避免随 `content.innerHTML` 替换被删除。
- 移动共享控件保留原节点、ID 与事件绑定，不复制按钮或重复绑定；任何时刻只能有一个对应节点。
- 页面专属组件与监听按既有生命周期卸载；异步回调更新界面前确认目标页面与容器仍有效，不覆盖已切换的页面。
- 不得以空值判断掩盖节点丢失，应修复节点归属与切换顺序。
- 修改渲染入口、工具栏位置或卸载流程后，验证“普通页面 → React 页面 → 普通页面”及返回原页面的连续切换，检查内容非空、节点唯一、按钮可操作且无运行时错误；娱乐记录回归至少覆盖与笔记、待办、年度计划、英语学习、健身、衣橱、维保与生活计划的往返切换。

### 表单布局与信息密度

- 按内容分配宽度：名称、备注、长链接可占整行；状态、平台、评分、日期与短数字使用紧凑宽度，不默认拉满整行。

## 功能行为与数据约定

### 行为 Product invariants

工作与私人数据隔离；来源为 WORKBENCH-PLAN.md、CLOUD-STORAGE.md 及服务端 API。保留记录级保存、冲突恢复、失败保留输入与防重复提交；界面统一不改变云端权限、数据格式或同步协议。

认证边界：浏览器使用签名 Cookie，并优先于缓存的 Authorization 头校验；有效 Basic 登录自动换签会话 Cookie，后续资源与轮询复用会话。Basic 入口与表单登录共享 D1 持久认证额度，每 IP 十分钟桶最多 10 次，Basic 成功请求也计数；超限返回 429，限流存储不可用返回 503，已有有效 Cookie 的业务请求不消耗额度。自动化频繁读取须使用登录会话，不能依赖反复提交账号密码；签名同步接口使用独立密钥与时间窗口，工作与私人空间因此不获得独立身份权限。

### 行为 Word practice

跟打显示英文，默写隐藏英文与音标直至查看答案或提交；IME 组合期间不提交。错误拼写不自动前进并允许修改；本轮拼错、查看答案或暂时不会记为不会，首次正确记为已掌握；每次成功提交增加复习次数并记录日期，首次学习日期已存在则保留。每词用原 `vocabulary` 记录级 patch 保存，失败保留输入并允许重试，不前进、不重复计数，成功后才进入下一词；统计只针对本轮，错词可单独重练，不宣称间隔重复算法。练习期间阻止外部导航与后台刷新，退出确认只影响未提交答案；朗读使用浏览器英语语音，失败明确提示并在退出时停止。

练习直接渲染在英语学习页，不用模态弹窗；词汇库独立路由 `vocabularyLibrary` 保留导入、搜索、熟练度筛选与词条，两页互有入口。练习中切词库须确认，设置与完成状态允许正常导航；跨页卸载 React 根并停止朗读，重进后正确重建，词汇库路由保持侧栏选中态。

### 行为 共享组件统一（2026-10-24 至 10-26）

动效落地：Animate UI 沿用现有 Radix Dialog API 提供弹窗与侧开面板动效，替换旧 CSS 入退场；顶部快捷导航用 Motion 共享布局背景，打卡保存成功后轻量缩放，共享弹窗用独立 translate 居中以免被 Motion transform 覆盖；待办表格按稳定 ID 入退场，退场行 inert 且焦点不回退到 inert 后代，仅成功保存后移除；娱乐封面悬停轻抬，筛选/排序按来源 ID 位置过渡，资料异步回补不重复触发；英语只对题目区淡入，输入框不重建；年度事项与编辑面板用 WorkspaceProgress 平滑过渡，训练比例只按实际勾选组数计算；SaveButton 用隐藏预留标签保持各状态宽度，保存中禁用，失败不丢输入。

主操作使用紫色实底、细微内高光与短阴影，辅助操作用浅色实底加清晰描边，悬停加深并显示短阴影，保留可见焦点与 44px 点击区；按钮颜色与层次由 `workspace-theme.css` 的 btn 令牌管理。普通主/辅助/轮廓按钮统一 44px、10px 圆角、14px，应用层 Button 将 outline 与 secondary 映射到同一浅底描边，不改固定上游；ghost 与 link 保留导航/文本用途，危险操作保留语义。原生适配与日历适配复用 `data-ui-control` 尺寸与语义令牌；顶部图标按钮为 44px/16px 浮岛变体，收起、搜索与通知共用同一外观；按钮与输入默认使用 semantic-border 浅灰细描边，聚焦态保留清晰提示。卡片阴影引用 `card-shadow`，不用可能被 Tailwind 作用域重定义的 `shadow-sm`。文件选择复用 `file-trigger.js` 创建可键盘操作的真实 button，保留原 input、事件、校验与禁用状态，禁止以不可聚焦的 label 代替动作按钮；共享日期网格与 Home/End 均以周日为首日。项目抽屉变体须同时清除独立 translate 与 transform。个人中心使用账号用途文案，不按是否含 form 推断为编辑；登录使用相同控件尺寸。

通知铃铛：顶栏通知入口复用 React Bits BellToggle 的 action 变体，只打开既有到期提醒弹窗，不表示订阅开关、不新增通知设置或集合、不使用 `aria-pressed`。共享 `wb-icon-button` 管理 44×44px、16px 圆角、浅灰描边、焦点与禁用；计数来源与 `wb-notification-count` 归属保留，零项隐藏、超 99 显示 99+。就绪且有提醒时间歇摇铃并显示声波，约每 5 秒一轮、每轮约 820 毫秒，数量仍大于零时保持节奏不重启；清空提醒、禁用、减少动态、页面隐藏或卸载立即停止并清理定时器与动画，恢复可见且仍有提醒时恢复。点击与键盘只打开列表，不新增播报或自动弹窗。
