# 开发规则

本文件记录工作台项目的开发要求，后续新增或修改页面时均须遵守。

## 1. 页面内容不能超出整个页面

- 所有页面及组件必须适应当前可视区域，桌面端和移动端均不得出现横向溢出、内容越界或控件被裁切。
- 长文本、图片、GIF、表单、卡片及弹窗须在所属容器内合理换行、缩放或布局，不能撑破页面。
- 内容高度超过可视区域时，必须可以正常纵向滚动，确保所有内容和操作按钮可见、可达。
- 表格等确需横向滚动的内容，应限制在其自身容器内，不得导致整个页面横向滚动。
- 不得仅通过隐藏溢出来掩盖布局问题，也不得以裁切内容或按钮作为解决方式。
- 修改后须检查桌面及窄屏布局，测量主要容器的实际边界，并验证按钮可点击；不能只以页面没有横向滚动条作为验收依据。

## 2. 弹窗与抽屉统一开发要求

- 弹窗和抽屉的定位、宽高、最大高度及滚动区域由共享 Dialog / Sheet 组件统一管理。原生表单适配进共享组件后，旧容器不得继续保留固定定位、视口高度或独立宽度等冲突规则；应在原规则处排除已适配节点。
- 同一个弹窗只显示一套标题、说明和关闭按钮。适配旧页面时须隐藏旧标题栏及重复关闭按钮，保留业务代码依赖的原节点、ID、事件监听和保存逻辑；外部打开链接等独立操作应保留。
- 宽预览、个人中心、项目抽屉等尺寸差异须通过共享组件的明确变体或尺寸变量表达，不得靠旧页面选择器或追加高优先级样式覆盖。
- 抽屉采用固定头部与可滚动正文时，正文须允许收缩（如 flex 布局中的 min-height: 0），不得用正文最小高度撑出整个弹层。底部保存、取消及删除操作必须能够滚动到并点击。
- 长标题须合理换行或限制展示行数，不能挤压关闭按钮、覆盖说明或使正文失去可用高度；完整内容仍须可在相应字段中查看。
- 自动聚焦只能落到可见、可交互的控件，不能聚焦已隐藏的旧关闭按钮。关闭后应恢复合理焦点，取消和保存失败时须保留既有恢复行为。
- 修改共享弹窗逻辑后，须联查个人中心、消息通知、游戏发售列表、Google 表格预览、项目编辑与新增、笔记及衣物编辑，并检查 React 待办、年度计划和日历日程面板是否受到影响。
- 验收须等待入场动画结束，分别检查桌面和窄屏的实际弹层边界、重复标题与关闭按钮、内部滚动、底部操作可达性，以及保存、取消、失败恢复和焦点返回。不得只验证单个页面或只检查 document.scrollWidth。
