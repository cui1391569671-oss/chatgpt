# ilamy Calendar integration

Official package: `@ilamy/calendar@3.2.1` (MIT), https://github.com/kcsujeet/ilamy-calendar.

The calendar, default event form, date/time pickers, recurrence-scope dialog, view toolbar,
ICS export, and drag-to-create/recurrence/agenda plugins come from the upstream package.
No `renderEventForm` override and no local copy of the old event form are used.

The workbench integration owns scope isolation, stable IDs, atomic `onEventsChange`
persistence, failed-write retry/discard, source-task/project routing and deletion confirmation.
The official form's fields receive application limits/inline title validation at the portal boundary.
The package's English color names are retained. Events are stored as Beijing wall times; RRULE
Dates/exclusions retain their ISO instants. Legacy rules are adapted without mutating stored data.

Build from project-tracker:

```
npm run build:calendar
npm run build:pages
npm test
```

`package-lock.json` pins dependencies. `build.mjs` bundles React and ilamy, generates scoped
Tailwind CSS, and creates `../ilamy-assets.mjs` and `../ilamy-recurrence-runtime.mjs`.
These generated modules travel with the Worker; the running website does not use a CDN.
`build-pages.mjs` consumes the generated modules without requiring a frontend install.
Whenever this directory changes, rebuild the calendar before generating pages/deploying.

CSS utilities are scoped to `.ilamy-surface` and marked Radix portals. Global workbench
`hidden` utilities exclude those surfaces. Tokens map from workspace-design.css's
`--accent/--surface/--text/--line` through `--ilamy-*` to the scoped shadcn variables.

Upstream MIT text is in ILAMY-LICENSE.txt. Bundled dependency notices are generated by
esbuild and served with the package license at `/assets/calendar.js.LEGAL.txt`.
