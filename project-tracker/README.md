# 项目问题跟进表
独立目录，数据保存在 Cloudflare D1，仓库不包含真实项目数据或密码。

## 一次性连接
现有 Worker project-tracker → Settings → Builds 连接本仓库。
生产分支 main；根目录 project-tracker。
构建命令 npm run build；部署命令 npx wrangler deploy --keep-vars。
构建变量 CF_D1_DATABASE_ID 填现有 project-tracker-db 数据库 ID。
保留运行时 TRACKER_USER、TRACKER_PASSWORD Secrets。
可设置监听路径 project-tracker/**。
部署不执行初始化 SQL，不改写项目数据。现有数据库需已初始化。
每天北京时间18:00归档已完成问题。首次部署后检查登录、数据、保存及项目管理，再处理域名。

## 首次构建检查
连接仓库后，如果构建历史为空，先确认生产分支为 main、根目录为 project-tracker，监听路径包含 project-tracker/**。向该目录提交更新后，到 Deployments 页面中的 Go to build history 检查是否出现对应提交的构建记录。没有记录时需排查仓库连接和触发设置；有失败记录时查看日志。代码已提交不代表已上线，需确认生产部署完成并验证项目管理按钮。

## 双工作台（仅本人使用）

首页 `/` 是空间选择入口，`/work` 是工作工作台，`/personal` 是私人工作台。两边都有独立的待办、笔记和日程。
原项目问题表位于 `/projects`，从工作工作台进入。
两个工作台沿用现有 TRACKER_USER 和 TRACKER_PASSWORD 登录，适用于仅本人使用。
日程时间按北京时间录入，不连接外部日历，也不发送系统通知。

数据保存在现有 `tracker_state` 记录中，原 `workspace` 归入私人范围，新增 `workWorkspace` 保存工作范围；无需新建数据库或初始化 SQL。
两边维护独立版本号，互相保存不会造成工作台版本冲突。底层更新仍使用原子版本检查，避免并发覆盖。
项目接口仅返回项目字段；项目保存与每日归档保留两边工作台的数据和版本。

修改 `index.html`、`workbench.html` 或 `landing.html` 后运行 `npm run build:pages`，生成 Worker 使用的 `pages.mjs`，并将生成文件一起提交。
Cloudflare 原构建命令 `node configure.mjs` 仍可部署提交中已生成的页面，建议改为 `npm run build` 自动生成。
运行 `npm test` 验证数据保留、空间隔离、版本冲突、归档、输入校验和页面路由。

## 日历与工作台切换

工作和私人空间均提供月历，可切换月份、返回今天、按日期查看及新增日程。跨天日程在覆盖的日期内显示，搜索同步筛选月历标记与当天安排。
导航中提供直接切换到另一工作台的按钮，也可返回工作台选择入口。

## 中国节假日与调休

`holidays.json` 保存已核对的官方年度放假区间和补班日期，目前收录 2026 年官方放假调休及 2027 年节日日期。
月历与当天详情显示节日名称、休息标记及调休补班标记，工作和私人空间共用这套公共日历数据。
没有收录的年份明确提示缺少官方安排，不推算补班。
修改年度数据后运行 `npm run build:pages`，更新 HTML 中的嵌入数据及 Worker 页面。
新增年度安排需按国务院办公厅年度通知核对。

新功能发布前须获得用户针对本批改动的明确同意；开发、测试和草稿 PR 不代表授权合并生产分支。

## 项目表视觉规范

项目问题表沿用工作台背景、文字、主色、细边框和卡片圆角；按钮与筛选控件采用统一尺寸，表头使用浅色背景，手机筛选栏分行布局，宽表仅在表格容器内横向滚动。


### v1.1.0 衣橱预览

两个工作台侧栏显示版本号。私人工作台新增“我的衣橱”：上传 JPG/PNG/WebP 照片（浏览器压缩为最长边640px、最多180KB的JPEG），按类别、颜色和季节管理衣服，手选单品保存搭配，按类别和季节生成基础组合。基础组合是规则筛选，不进行图片识别或真人试穿。

照片通过登录保护的接口保存到现有 D1 的 wardrobe_images 独立表，首次使用时创建；衣服信息与穿搭保存在私人 workspace 中，保留工作/私人隔离。删除衣服同时移除引用它的穿搭；暂不清理图片表中的历史照片，以免误删并发引用。代码的 Google Drive ZIP 备份不包含云端衣橱照片或数据库。新批次上线仍需要用户明确同意。

## 工作空间 Google Drive 入口

工作工作台新增 Google Drive 栏目，可在新标签页打开网盘，并添加、搜索、编辑或移除常用 Google 文件和文件夹链接。链接只接受 drive.google.com / docs.google.com 的 HTTPS 地址，保存到工作空间 driveLinks 字段，沿用版本检查与并发合并，无需数据库迁移。移除卡片只删除工作台的链接记录，不删除 Google 文件。

使用步骤：Google Drive → 新建常用文件 → 输入名称、Google 文件或文件夹链接及可选备注 → 保存 → 打开文件。Google 登录、文件权限、预览和正文编辑由 Google 页面处理；本功能无需 API 密钥或 OAuth 配置，不自动读取网盘内容。

本地已使用模拟接口检查新增及编辑卡片、搜索入口、桌面与390px手机布局；实际云端持久化与 Google 账号访问需发布后验证。发布仍需用户针对本批改动明确同意。

### Google 表格内嵌预览

Google Sheets 常用卡片默认显示“预览表格”，在当前工作台弹窗内加载 Google 预览页面，支持普通表格链接和已有的发布链接，并保留 gid 工作表定位。关闭弹窗停止加载；另保留用户手动选择的“在 Google 中打开”入口。其他文件仍沿用外部打开。

内嵌加载沿用 Google 文件权限，未改变分享设置；私有表格可能受 Google 登录、第三方 Cookie 或嵌入限制影响。本地用演示链接验证了按钮、弹窗和不跳转行为，尚未验证真实 Google 表格内容。无需将文件公开发布。

## 项目问题同步工作日历

工作日历按项目问题的计划日期显示尚未完成的问题，包括进行中和暂停状态。月历显示项目问题数量，当天详情显示项目名称、问题、状态、原因与备注，并提供进入问题表的入口。没有日期、无效日期、已完成及归档问题不显示；私人日历不读取项目问题。

日历通过受登录保护的只读 /api/project-calendar 接口实时派生，不复制到手动 events，因此改期、完成、删除不会留下重复日程。进入日历、回到页面、问题表内保存成功时刷新；停留在日历时每30秒检查云端，也可手动刷新。失败时保留上次结果并提示同步失败。无需数据库迁移。

## 空间内统一到期提醒

工作工作台的提醒汇总工作待办和项目问题（按计划日期）；私人工作台只汇总私人待办，包括游戏记录。受登录保护的 /api/reminders 接口必须指定 work 或 personal，两个空间不混合。

提醒展示未完成的已逾期、今天和明天到期任务，按北京时间判断并按日期排序，标明任务来源与日期。项目暂停但未完成仍提醒，无日期、已完成及归档问题不提醒。点击待办进入编辑，点击项目问题进入项目问题表。

首次加载、打开提醒、页面回到前台、保存或删除待办、内嵌项目表保存成功后刷新，页面可见时每30秒检查更新。同步失败保留已有内容并提示失败。各栏目共用工作台顶部提醒入口；笔记、衣橱、词汇和 Drive 链接没有截止日期，不产生到期任务。

## 自动同步检查与修复

修复问题表与工作台共用整库版本导致的误报冲突：新问题表保存请求携带读取时的项目基线，后台在项目内容未变化时可跨越工作/私人空间写入引起的版本变化，原子重试并保留最新工作台数据。真正的项目变更仍返回冲突，不自动覆盖。

连续编辑时，前一笔保存成功后更新下一笔待保存数据的基线；网络恢复与可见页面定时检查会重试未保存的数据。真正冲突显示核对本地副本入口，核对窗口读取最新云端，“保留云端”会重新加载云端并解除暂停。历史未同步副本继续保留，须核对后选择恢复或保留云端，不静默丢弃。

工作/私人工作台的待办、笔记、日程、Drive链接、词汇及衣橱通过空间版本每30秒及回到前台时检查更新；打开编辑弹窗时不替换数据，保存期间或版本变化后丢弃旧读取响应。问题表也检查云端更新，编辑单元格、日期或打开弹窗时不替换页面。日历刷新中收到新的保存通知会在完成后再次读取；提醒点击待办前读取最新工作台，已删除任务不打开空白编辑器。

验证覆盖工作/私人数据隔离、工作台保存后旧问题表保存、真实项目冲突保护、原子写入竞争、连续编辑基线、背景读取与保存竞争、项目完成后日历及提醒移除，以及现有衣橱、词汇、链接、笔记、日程的数据保留测试。使用本地真实Worker和模拟数据库完成浏览器问题表编辑与工作台交替保存，未连接生产数据库写入测试。
